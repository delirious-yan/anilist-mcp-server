### 4.3 Findings / Minor Technical Observations
- **Observation 1 (Date Handling for Missing Pre-States):** In `sync-anilist-request.mjs` line 118:
  ```js
  for (const field of ["startedAt", "completedAt"]) {
    if (before[field] && JSON.stringify(before[field]) !== JSON.stringify(after[field]))
      throw Error("Unexpected change to " + field);
  }
  ```
  If `before` entry had `startedAt: null`, `before[field]` evaluates to `null` (falsy), so `if (before[field])` does not execute. If AniList's API automatically populates `completedAt` on setting `status: COMPLETED` for a previously empty entry, this check allows `after.completedAt` to be populated without throwing an error. This is intentional and realistic behavior for new list completions on AniList.
- **Observation 2 (Sequential Non-Transactional Batches):** As documented in `docs/anilist-sync-workflow.md`, batch updates execute sequentially in a `for` loop. If entry 2 fails, entry 1 remains applied on AniList. The test suite (`test 11`) and documentation correctly address this by verifying item-level logging so partial applications are accurately reported.
