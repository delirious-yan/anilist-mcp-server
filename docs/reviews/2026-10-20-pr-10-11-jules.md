### 4.2 Detailed Technical Analysis & Code Structure

#### A. Sync CLI Output Enhancement (`scripts/sync-anilist-request.mjs`)
- **Lines 84–97:** Introduces boolean `changed = before?.status !== "COMPLETED" || before?.progress !== request.progress;`.
- **Line 132:** Appends ` outcome=APPLIED` or ` outcome=ALREADY_CORRECT` to the standard `VERIFIED account=Luciedmeo mediaId=...` log line.
- **Correctness:**
  - The `VERIFIED` line is emitted **only after** independent authenticated readback (`after = (await read(request)).mediaListEntry`) passes status/progress validation and field-preservation checks.
  - If an entry was already completed with matching progress prior to execution, `changed` is `false`, so no `SaveMediaListEntry` GraphQL mutation is sent, and the log reflects `outcome=ALREADY_CORRECT`.
  - If a mutation was issued, `changed` is `true`, and after successful post-mutation readback, the log reflects `outcome=APPLIED`.

#### B. Isolated Test Fixture Adapter (`scripts/fixtures/anilist-sync-fetch.mjs`)
- **Purpose:** Preloaded via `node --import ./scripts/fixtures/anilist-sync-fetch.mjs` during test execution.
- **Isolation & Network Safety:**
  - Reads synthetic responses from `process.env.ANILIST_SYNC_FIXTURE`.
  - Replaces `globalThis.fetch` with `fixtureFetch`.
  - Validates URL is strictly `"https://graphql.anilist.co"` and method is `"POST"`.
  - Asserts response queue is non-empty (`assert.ok(fixture.responses.length, "Unexpected GraphQL call; no network allowed")`). This guarantees zero network leakage during tests.
  - Intercepts pacing delays by overriding `Date.now = () => (clock += 3000)`, allowing tests to run instantaneously without real clock delays.

#### C. Test Suite Architecture & Precise Execution Boundaries (`scripts/sync-anilist-request.test.mjs`)
- **Process Isolation & Environment:**
  - `spawnSync` in `sync-anilist-request.test.mjs` does not pass a `cwd` option. Therefore, while `requestPath`, `fixturePath`, and `tracePath` are created inside an isolated temporary directory (`mkdtempSync`), the spawned child Node process runs with the repository root as its working directory.
- **Fixture Consumption & Assertion Coverage:**
  - `fixtureFetch` shifts fixture responses sequentially from `fixture.responses` strictly by call order.
  - `sync-anilist-request.test.mjs` asserts GraphQL mutation variables (e.g. confirming `SaveMediaListEntry` carries only `{ id, progress }` and excludes `score`/`notes`/`dates`), but it does not validate all GraphQL query strings, selection sets, or read variables sent during query calls. The coverage boundary is specific to mutation parameters and overall process execution state.
- **Readback Scope & Validation Boundaries:**
  - In `sync-anilist-request.mjs`, the readback call `const after = (await read(request)).mediaListEntry;` extracts `mediaListEntry` from the second `read()` response.
  - The script checks `after.status === "COMPLETED"` and `after.progress === request.progress`, and compares preserved entry fields (`id`, `score`, `notes`, `repeat`, `priority`, `private`, `hiddenFromStatusLists`, `customLists`, `advancedScores`).
  - **Limitation:** The script does not re-validate `Media.id`, `Media.type`, `Media.episodes`, or `Media.title` on the second `read()` call (they are validated on the initial read prior to mutation). Readback validates the updated list entry state, not top-level Media object attributes.
- **Date Check Limitation (`startedAt` / `completedAt`):**
  - Lines 118–121 of `sync-anilist-request.mjs`:
    ```js
    for (const field of ["startedAt", "completedAt"]) {
      if (before[field] && JSON.stringify(before[field]) !== JSON.stringify(after[field]))
        throw Error("Unexpected change to " + field);
    }
    ```
  - **Limitation:** The guard `if (before[field])` only compares dates when `before[field]` is truthy.
    - *Case 1 (No prior list entry):* When `before` is `null`/`undefined`, the loop over `before` fields is skipped entirely.
    - *Case 2 (Existing list entry with null date):* If an existing entry has `startedAt: null` or `completedAt: null`, `before[field]` is falsy. If AniList's API mutates or populates dates on completion, `before[field]` evaluates to falsy, bypassing the comparison. This behavior is a code limitation in the preserved-field comparison logic rather than an established property of AniList's API.

#### D. Package Integration (`package.json`)
- Adds `"test:sync": "node --test scripts/sync-anilist-request.test.mjs"`.
- Appends `&& npm run test:sync` to both `"test"` and `"test:coverage"` scripts.

- Explicitly distinguishes public title verification from authenticated account state.
- Emphasizes that CI passing and mutation echoing are insufficient without authenticated readback.
